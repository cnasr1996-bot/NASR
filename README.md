# NASR Photo Booth — سوفتوير شاشة البوث

سوفتوير بوث تصوير ذاتي: بث مباشر من كاميرا Canon، عد تنازلي، معاينة الصورة بتأثير **فنتيج**، دفع ذاتي (مدى / Apple Pay)، ثم طباعة تلقائية على طابعة **DNP**. الواجهة بالعربي والإنجليزي.

> 📋 **قبل شراء الأجهزة اقرأ:** [docs/HARDWARE.md](docs/HARDWARE.md)
> 🔧 **تركيب الأجهزة وتشغيل الكشك:** [docs/SETUP.md](docs/SETUP.md)

## رحلة المستخدم

```
الشاشة الترحيبية ──لمس──▶ تصوير (Live View + عد تنازلي) ──▶ معاينة (فنتيج)
       ▲                        ▲            إعادة التصوير │        │ اطبعها
       │                        └──────────────────────────┘        ▼
       │                                                      الدفع (يتحفز الجهاز تلقائياً)
       │                                              نجح │              │ فشل / انتهى الوقت / إلغاء
       └──── شاشة الشكر ◀──── الطباعة ◀─────────────────────┘              ▼
                                                                   رسالة + "حاول مرة أخرى"
```

- **45 ثانية بدون تفاعل** في أي شاشة تنتظر العميل ← يرجع للشاشة الترحيبية تلقائياً (مع تنبيه "هل ما زلت هنا؟" قبلها بـ 10 ثواني).
- قبل الدفع يتأكد السوفتوير أن الطابعة جاهزة وفيها ورق — **ما يأخذ فلوس على صورة ما راح تنطبع**.
- لو الطابعة خلص ورقها أو فيها خطأ ← الشاشة الترحيبية تتحول لـ "الجهاز متوقف مؤقتاً" + تنبيه للمشغّل.
- لو صار خطأ طباعة بعد الدفع ← تظهر رقم مرجعي للعميل، والصورة محفوظة في `Pictures/PhotoBooth` لإعادة الطباعة.

## التشغيل للتطوير (بدون أي أجهزة)

```bash
npm install
npm start        # يفتح البوث بكاميرا اللابتوب + دفع وطباعة تجريبية
npm test         # اختبارات منطق البوث والفلتر والترجمة
```

الإعدادات الافتراضية في `config/default.json`. لكل بوث إعدادات خاصة ضعها في `config/local.json` (تتجاوز الافتراضية). مثال للتشغيل الفعلي:

```json
{
  "camera":  { "driver": "canon" },
  "printer": { "driver": "windows", "deviceName": "DP-DS-RX1HS" },
  "payment": { "driver": "mock" },
  "flow":    { "price": { "amount": 25, "currency": "SAR" } },
  "attract": { "video": "assets/attract.mp4" }
}
```

| الإعداد | المعنى |
|---|---|
| `flow.idleTimeoutMs` | مهلة عدم التفاعل (45000 = 45 ثانية) |
| `flow.paymentTimeoutMs` | أقصى وقت انتظار جهاز الدفع |
| `flow.countdownSeconds` | العد التنازلي قبل التصوير |
| `flow.maxRetakes` | عدد مرات إعادة التصوير المسموحة |
| `camera.driver` | `webcam` (تطوير) أو `canon` |
| `printer.driver` | `mock` (تطوير) أو `windows` (طابعة DNP عبر تعريف Windows) |
| `printer.mediaCapacity` | عدد الطبعات في الرول (700 لـ DS-RX1HS) |
| `printer.lowMediaWarning` | ينبّه المشغّل لما يبقى هذا العدد |
| `print.vintage` | قوة تأثير الفنتيج (sepia, warmth, fade, vignette, grain) |
| `print.caption` | النص اللي يطلع أسفل الصورة المطبوعة |
| `operator.webhookUrl` | رابط يستقبل تنبيهات الورق/الأخطاء (اختياري) |

**اختصارات المشغّل (كيبورد):** `Ctrl+Shift+M` بعد تركيب رول جديد (يصفّر العدّاد) — `Ctrl+Shift+Q` للخروج من وضع الكشك.

## هيكل المشروع

```
src/
  core/            منطق بدون أجهزة — قابل للاختبار
    flow.js        آلة الحالات: الشاشات، المهلات، الدفع، الطباعة
    vintage.js     فلتر الفنتيج (يشتغل على البكسلات مباشرة)
    i18n.js        نصوص العربي والإنجليزي
  hardware/        درايفر لكل جهاز، بنفس الواجهة للتجريبي والحقيقي
    camera/        webcam (تطوير) + canon-edsdk
    printer/       DNP عبر Windows + عدّاد الرول + حالة الطابعة
    payment/       mock — ينضاف درايفر المزوّد بعد اختياره
  main/            Electron: النافذة، الطباعة الصامتة، التنبيهات
  renderer/        واجهة اللمس (HTML/CSS/JS)
test/              اختبارات
docs/              توصيات الأجهزة وخطوات التركيب
```

## الحالة الحالية

| الجزء | الحالة |
|---|---|
| رحلة المستخدم + مهلة 45 ثانية + إلغاء الدفع | ✅ جاهز ومختبر |
| الواجهة عربي/إنجليزي + الانتقالات + إحساس اللمس + أيقونة الانتظار | ✅ جاهز |
| تأثير الفنتيج + تصميم الصورة المطبوعة 4×6 | ✅ جاهز |
| الطباعة الصامتة لـ DNP + تنبيه الورق + حالة الطابعة | ✅ جاهز — يحتاج تجربة على الطابعة الفعلية |
| كاميرا Canon (Live View + سحب الصورة) | ✅ مكتوب — يحتاج EDSDK من كانون وتجربة على الكاميرا الفعلية |
| جهاز الدفع | ⏳ بانتظار اختيار المزوّد ووثائق ECR (فيه درايفر تجريبي حالياً) |
